## 2. 完整股池流转机制

- 状态：待处理
- 记录时间：2026-05-05
- 优先级：高

### 背景

当前已落地的是“最小可用股池”：

- 一句话选股结果可勾选后加入本地股池
- 股池具备 `pool_type` 字段
- 股池内股票保留了来源模块、来源查询和来源 run_id
- 监听策略已具备独立事件触发能力，但尚未与股池流转联动

后续目标不是简单的“触发预警后自动加入一个股池”，而是把监听模块、股池模块、自选股模块串成一个统一的“事件驱动流转系统”。

### 已对齐的业务约束

- 股票可以同时存在于多个股池
- 代码层面不强行设计股池层级，但业务上允许存在“信号池 / 确认池 / 择时池 / 自选池”等不同角色
- 流转以“移动”为主，但不是全局唯一归属，允许按规则保留在其他池中
- 同一只股票在同一天内只允许自动流转一次
- 每次流转都必须记录来源事件、来源策略、进入原因
- 需要区分“自动流转”和“人工操作”
- 一个监听策略允许配置多个流转动作
- 流转动作模型对所有监听策略统一，策略本身只负责“是否触发”

### 推荐架构

建议按以下四层拆开，而不是把“进股池”逻辑写死在某个监听策略中：

1. 监听事件层

- 当股票触发监听时，先记录一条标准化事件
- 建议字段：
  - `event_id`
  - `ts_code`
  - `strategy_type`
  - `trigger_type`
  - `trigger_time`
  - `trigger_price`
  - `message`
  - `params_snapshot`

2. 流转规则层

- 单独存储“某类监听触发后应该如何流转”
- 一个策略可配置多个动作
- 建议字段：
  - `rule_id`
  - `strategy_type`
  - `enabled`
  - `from_pool_ids`
  - `to_pool_id`
  - `mode`：`move | copy`
  - `cooldown_days`：默认 `1`
  - `conditions`
  - `priority`

3. 流转执行层

- 监听触发后，不直接修改股池
- 统一交给执行器判断：
  - 今天是否已经自动流转过
  - 当前是否已在目标池
  - 是否需要从来源池移出
  - 是否需要保留在其他池
  - 是否需要同时发送企业微信通知

4. 流转日志层

- 单独记录每次流转，便于追踪与审计
- 建议新增集合：`pool_transition_logs`
- 建议字段：
  - `transition_id`
  - `event_id`
  - `rule_id`
  - `ts_code`
  - `strategy_type`
  - `action_type`
  - `from_pool_ids`
  - `to_pool_id`
  - `operator_type`：`auto | manual`
  - `status`
  - `reason`
  - `created_at`

### 推荐数据模型增强

建议后续增强 `stock_pools.stocks[*]` 的元信息，而不是只保留基础来源字段：

- `source_type`
- `source_strategy`
- `source_event_id`
- `operator_type`
- `entered_at`
- `last_transition_at`
- `status`
- `tags`
- `note`

这样后面做“观察期、遗弃标准、人工确认、择时确认”时会更容易扩展。

### 推荐落地顺序

第一阶段：最小可用版

- 为监听策略增加可选动作：`触发时移动到指定股池`
- 支持企业微信通知与股池流转同时进行
- 支持 `1` 天冷却
- 记录自动流转日志

第二阶段：标准版

- 一个策略支持多个流转动作
- 支持来源池限制
- 支持手工流转与自动流转统一记录
- 为股池详情补充来源事件和进入原因展示

第三阶段：完整流转版

- 支持更复杂的条件组合
- 支持更完整的“信号 -> 确认 -> 择时 -> 自选”路径
- 支持遗弃条件、失效条件和回退流转
- 视行情环境引入不同的流转规则模板

### 建议方向

- 先保持当前 `stock_pools` 结构可用，不急着大改已有页面
- 下一步优先补：
  - `listener_trigger_events` 或同等事件集合
  - `pool_transition_logs`
  - 监听后的流转规则配置入口
- 监听策略本身只负责发出标准化触发事件，不直接嵌入复杂流转逻辑

### 背景

当前交割单复盘已经支持打开对应 K 线并定位买卖点，但部分股票本地 `stock_daily` 历史仍不完整，导致：

### 后续方向

- 优先为交割单涉及的股票补齐历史日线
- 至少保证复盘所需标的具备更长周期的本地 K 线
- 结合现有 `stock_daily` 全历史补齐计划，优先处理交割单高频出现的股票

### 当前已知待调整点

- 当前第一版自动流转实现中，`来源股池` 仅部分参与“移动时从哪些池中移出”的逻辑。
- 这意味着：如果某条规则已经配置了来源股池，但股票只是被手动加入监听、并不在这些来源池里，当前实现仍可能执行流转。
- 这与当前已对齐的业务预期不一致。

#### 后续需要修正为

- 自动流转规则必须始终存在明确来源
- `来源股池` 应支持多个
- 规则语义应为：
  - 股票当前必须命中这些来源股池中的至少一个
  - 命中后才允许执行流转
- 不再保留“无来源池限制即可直接流转”的默认路径

#### 当前处理决定

- 先保留现有代码，不在本轮继续修改
- 将该问题视为后续必须处理的流转规则语义修正项
