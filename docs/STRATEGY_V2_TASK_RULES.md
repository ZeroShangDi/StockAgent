# Strategy V2 任务创建规则

## 1. 目的

本文档是 Strategy V2 场景任务创建表单与后端校验的规则源。

任务由四层组成：

- 基础信息：任务名、任务说明、任务策略。
- 策略参数：默认使用策略参数，可在当前任务内覆盖。
- 场景信息：场景类型、目标范围、调度方式。
- 调度动作：当策略输出 `1` / `0` / `-1` 后，由任务决定执行什么动作。

策略本身仍然是纯函数，不直接发通知、不直接流转股池、不直接写交割单。

## 2. 场景类型

| 场景 | code | 说明 | 支持目标范围 |
| --- | --- | --- | --- |
| 选股 | `scan` | 找出符合策略的股票，进入候选、复盘或计划制定链路 | 自选股、持仓股/交易账户、股池分组、全市场排除 ST |
| 监听 | `listen` | 按频率监听目标对象，触发通知、股池流转或风险提醒 | 自选股、持仓股/交易账户、股池分组、全市场排除 ST、自定义股票列表、指数 |
| 回测 | `backtest` | 对历史区间执行策略，输出运行结果和分析数据 | 全市场排除 ST |
| 模拟 | `sim_trade` | 基于实盘/准实盘数据更新模拟账户和交易记录 | 全市场排除 ST |

备注：

- 场景类型和目标范围是多对多关系，不是简单一对一。
- 前端表单展示全部目标范围，但不可选项置灰。
- 后端必须重复校验，不信任前端置灰。

## 3. 目标范围

| 范围 | code | 是否股票范围 | 说明 | 额外参数 |
| --- | --- | --- | --- | --- |
| 自选股 | `watchlist` | 是 | 当前用户自选股列表 | 无 |
| 持仓股/交易账户 | `trade_account` | 是 | 从某个交割单分组推导当前持仓 | `trade_review_group_id` |
| 股池分组 | `stock_pool` | 是 | 选择一个现有股池 | `stock_pool_id` |
| 全市场排除 ST | `all_market` | 是 | 全 A 市场，默认排除 ST | `start_date`、`end_date`、`exclude_st`、回测/模拟任务需要 `trade_review_group_id` |
| 自定义股票列表 | `custom_stock_list` | 是 | 股票列表存储在当前任务下 | `ts_codes` |
| 指数 | `index` | 否 | 上证、深证、创业板等指数 | `index_code` |
| 事件 | `event` | 否 | 预留，不进入 V1 开发 | 暂无 |

默认：

- 选股/回测选择 `all_market` 时，默认时间段为最近三个月。
- 回测选择 `all_market` 时，必须选择或创建一个交割单分组作为回测账户，用于生成最终交割单数据和结果分析。
- 模拟选择 `all_market` 时，必须选择或创建一个交割单分组作为模拟交易账户，用于每日按真实数据更新。
- 事件范围本期只保留字典项，前端置灰，后端拒绝创建。

## 4. 调度方式

| 调度 | code | 支持场景 | 说明 |
| --- | --- | --- | --- |
| 一次性运行 | `once` | 选股、回测 | 创建后执行一次或手动触发一次 |
| 定时运行 | `scheduled` | 选股、监听、模拟 | 按内置时间点或轮询频率运行 |
| 手动运行 | `manual` | 选股、监听、回测、模拟 | 只保存任务，由用户手动运行 |

定时运行选项：

| 名称 | slot | 说明 |
| --- | --- | --- |
| 盘前 9:00 | `pre_market_0900` | 交易日前置扫描 |
| 竞价 9:25 | `call_auction_0925` | 集合竞价阶段 |
| 上午变盘 10:00 | `morning_turn_1000` | 上午行情初步确认 |
| 盘中轮询 1 分钟 | `intraday_1m` | 高频监听 |
| 盘中轮询 5 分钟 | `intraday_5m` | 常规监听 |
| 盘中轮询 30 分钟 | `intraday_30m` | 低频监听 |
| 中午收盘 11:30 | `midday_close_1130` | 午间复盘 |
| 下午变盘 14:00 | `afternoon_turn_1400` | 尾盘前确认 |
| 盘后 15:05 | `post_market_1505` | 收盘后整理 |
| 每周六 12:00 | `weekly_sat_1200` | 周期性回放或训练 |

## 5. 调度动作

动作按规则配置，一条规则表示：

`策略返回值命中 -> 执行动作 -> 使用动作参数`

| 动作 | code | 可用条件 | 参数 |
| --- | --- | --- | --- |
| 通知 | `notify` | 场景类型为监听 | 通知渠道、通知频率 |
| 加入股池 | `add_to_pool` | 目标范围是股票范围：自选股、持仓股/交易账户、股池分组、全市场排除 ST、自定义股票列表 | 目标股池、重复处理 |
| 股池流转 | `pool_transition` | 目标范围为股池分组 | 复制、移动、删除 |
| 临时清单 | `temp_list` | 调度方式为一次性运行 | 自动生成候选池股池，一天后删除 |
| 模拟成交 | `paper_trade` | 场景类型为回测或模拟 | 交割单账户、成交写入方式 |

通知频率沿用原市场监听逻辑：

- `once_per_trigger`：每次触发一次。
- `close_after_notify`：提醒后关闭。
- `unlimited`：不限次数。

## 6. 当前设计判断

回测和模拟任务的交易账户放在目标范围参数里：

- `scope_type = all_market`
- `params.trade_review_group_id = xxx`

原因：

- 交易账户决定任务运行的账户上下文。
- 后续持仓、净值、交割单分析都应按账户归集。
- `paper_trade` 动作只决定是否写入模拟成交/回测成交，以及写入方式。

## 7. 回测与模拟的区别

- 回测：选择历史时间范围后一次性运行，直接生成最终交割单数据，主要用于收益、胜率、阿尔法等结果分析。
- 模拟：绑定交易账户后按真实数据每日更新，持续维护模拟持仓和交易记录，更接近实盘训练。

## 8. 待确认风险

- 监听全市场排除 ST 的成本较高：前端允许配置，但后端执行层需要限制默认频率或要求更窄过滤条件。
- 事件范围保留但不开发：前端置灰，后端校验拒绝，避免用户创建不可运行任务。
