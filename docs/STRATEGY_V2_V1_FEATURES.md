# Strategy V2 V1 功能清单

## 1. 文档目的

本文档用于明确 `Strategy V2` 第一阶段的功能范围。

本轮目标不是推翻整个项目，而是在现有项目基础上，新开发一套围绕“策略、监听、回测/模拟交易”的新主链路。

在新链路完全可用之前：

- 老功能先不动
- 老页面先不下线
- 股池、交割单、多用户、通知等现有辅助能力优先复用
- 后续完成替换后，旧策略/旧监听/旧回测链路再评估下线

## 2. 本轮重构范围

### 2.1 本轮重点重构

- 策略体系
- 监听体系
- 回测体系
- 模拟交易体系
- 上述体系之间的统一抽象

### 2.2 本轮明确复用

- 多用户体系
- 股池体系
- 交割单页面及分析能力
- 通知基础设施
- 行情与历史数据能力
- 现有登录、权限、用户配置能力

### 2.3 本轮不单独成模块

- 风控

说明：

风控在概念上保留，但在实现上并入监听任务体系，作为监听任务的一种高优先级用途处理，不再单独拆一套 V2 风控模块。

## 3. V1 核心设计原则

### 3.1 策略是纯函数

策略本身不带启停概念，不直接承担任务调度和业务动作。

策略职责只有：

- 接收输入上下文
- 输出统一信号

### 3.2 统一输出协议

所有策略统一输出：

- `1`
- `0`
- `-1`

其中：

- `1` 表示正向信号
- `0` 表示中性或不触发
- `-1` 表示反向信号

同时允许附带扩展信息：

- 信号强度
- 触发原因
- 标签
- 支撑数据
- 调试信息

### 3.3 场景决定动作

策略不直接发通知、不直接进股池、不直接写交割单。

动作由场景任务决定。

首批动作包括：

- 通知
- 加入股池
- 股池流转
- 生成临时列表
- 写入模拟交易结果
- 预留实盘买卖动作

### 3.4 多用户是硬要求

所有新模型和新运行记录都必须天然支持 `user_id` 隔离。

### 3.5 跨日记忆必须支持

不是每个策略都需要状态，但系统必须支持“策略跨日记忆”。

状态最低粒度到：

- 用户
- 场景任务
- 策略
- 标的

## 4. V1 需要落地的能力

### 4.1 策略中心 V2

V1 要求：

- 内置策略目录
- 策略元信息管理
- 策略参数定义
- 策略支持场景说明
- 策略试运行能力

V1 不做：

- AI 生成策略
- Skill 型策略执行体
- 用户在页面上自由编写复杂策略代码

### 4.2 场景任务中心 V2

V1 需要四类任务：

- 选股任务
- 监听任务
- 回测任务
- 模拟交易任务

每个任务都应支持：

- 创建
- 编辑
- 启用/停用任务本身
- 手动运行
- 定时运行
- 查看运行历史
- 查看最近触发结果

注意：

- 启停属于任务，不属于策略

### 4.3 选股任务

V1 需要支持两类选股：

#### A. 日内扫描选股

- 对全市场或指定范围进行日内扫描
- 输出候选列表
- 候选列表可以加入现有股池
- 候选列表可以保留为临时结果

#### B. 指定时段扫描

- 在指定时间范围内，按策略筛选符合条件的股票
- 用于训练、样本沉淀或类回测用途

V1 主路径应优先支持：

- 先选出候选
- 再进股池
- 再通过流转、监听、人工筛选形成交易计划

### 4.4 监听任务

V1 支持监听目标：

- 个股
- 股池
- 分组
- 持仓组
- 指数
- 市场整体

V1 支持配置项：

- 策略
- 目标范围
- 参数
- 监听频率
- 触发频率控制
- 动作
- 调度方式

V1 支持触发结果：

- 记录标准化触发事件
- 发送通知
- 加入股池或股池流转
- 记录执行日志

### 4.5 回测任务

V1 支持：

- 基于历史数据运行策略
- 形成买卖结果
- 生成可落到现有交割单体系的结果
- 可查看运行摘要和统计结果

V1 交易配置先收敛支持：

- 手续费
- 滑点
- 用户级默认配置

V1 暂不深入支持：

- 复杂仓位理论
- 多账户高级模型

### 4.6 模拟交易任务

V1 支持：

- 基于每日更新的实盘数据持续运行
- 更新持仓与交易结果
- 输出可进入现有交割单分析体系的数据

V1 不接券商实盘，只做模拟链路。

### 4.7 可解释性与审计

V1 必须支持：

- 任务运行日志
- 单次运行结果
- 单标的信号结果
- 动作执行结果
- 失败原因记录

## 5. 与现有模块的复用关系

### 5.1 股池

继续复用现有股池模块：

- 承接选股结果
- 作为监听来源对象
- 作为股池流转目标

本轮不重做股池主结构。

### 5.2 交割单

继续复用现有交割单体系：

- 承接回测结果
- 承接模拟交易结果
- 使用现有交割单分析页做分析

本轮重点是“新任务如何产出交割单数据”，不是“重做交割单分析页”。

### 5.3 通知

继续复用现有通知基础设施，只切换触发源。

### 5.4 多用户

继续复用现有多用户体系，但新模型必须天然按用户隔离。

## 6. 新旧系统并行原则

并行期原则：

- 旧策略页保留
- 旧监听订阅保留
- 旧回测入口保留
- 新系统走单独的 V2 页面和 V2 API

替换期原则：

- 新监听任务稳定后，替代旧监听订阅
- 新回测任务稳定后，替代旧回测入口
- 新策略中心稳定后，替代旧策略配置逻辑

清理期原则：

- 旧逻辑可下线
- 历史数据尽量保留
- 必要时只保留只读兼容

## 7. V1 完成标准

满足以下条件，可认为 V1 主链路成立：

- 内置策略可在 V2 中统一管理和试跑
- 可创建选股任务并把结果送入现有股池
- 可创建监听任务并触发通知或股池流转
- 可创建回测任务并生成可分析的交割单结果
- 可创建模拟交易任务并持续更新结果
- 所有运行均有日志、结果和用户隔离
- 旧功能仍可正常使用，不受 V2 开发影响
